# P2-07 校园社群推送时间 A/B 实验设计

## 目标

生成一个与 P2-06 完全独立的校园营销 A/B 实验项目，验证“上午 9:00 推送”和“晚上 20:00 推送”是否会影响校园社群内容的点击行为。

## 研究问题与假设

- 研究问题：校园社群推送时间是否会改变学生点击校园福利内容的意愿？
- A 版：上午 9:00 推送。
- B 版：晚上 20:00 推送。
- 假设：晚间推送更贴近学生空闲时间，因此 B 版点击率可能高于 A 版；最终以真实数据为准。

## 样本与主要指标

- 计划总有效样本：120 份；A、B 两组各至少 60 份。
- 发布周期：7 天，面向本校大学生校园社群。
- 有效样本：唯一登记参与者打开实验页形成一次曝光记录；预览、测试和重复参与不计入正式样本。
- 主指标：点击率 CTR = 点击人数 / 曝光人数。
- 次指标：完成率、A/B 样本数、点击绝对差值、相对变化。
- 样本不足时只做描述性统计，不提前声称显著。

## 页面链路

`index.html → project2.html → experiment.html → share.html → experience.html → aggregate.html/setup.html`

页面沿用参考成品的深色卡片、编号模块、A/B 方案预览、真实数据空状态、分享入口和汇总分析布局，但文案与数据键全部使用 P2-07 命名。

## 数据与隔离

- 独立目录：`E:\codex\p2-07-campus-push-time`。
- 独立 study key：`p2-07-campus-push-time-v1`。
- 独立 localStorage：`p207_*`。
- 独立 Worker/D1 目录和数据库绑定，不读取或写入 P2-06 数据。
- 参与登记只收集学号、姓名、班级；不收集手机号、地址和支付信息。
- `?preview=A` / `?preview=B` 只用于展示，不写入正式记录。

## 参与端行为

参与者登记后进入体验页。页面显示一张校园社群推文卡片，文案、封面、福利内容和按钮一致，仅时间标签不同。打开页面记录一次曝光；点击“查看校园福利”记录点击；完成后显示提交状态。刷新不会重新分流，也不会重复创建参与者。

## 统计规则

后台只汇总正式记录。没有数据时显示空状态；不生成随机样本。样本达到计划数后，可使用双比例检验比较 CTR；当前项目只负责真实数据记录和描述性汇总，最终显著性结论由课程报告根据实际数据填写。

## 验收标准

1. P2-07 页面和 P2-06 页面目录、数据键、Worker API 互不复用。
2. 正式参与者固定在 A 或 B；刷新不变；重复提交按 participant_id 去重。
3. 预览模式不写入正式 localStorage 或云端。
4. A/B 只有推送时间不同，文案、封面、优惠和按钮一致。
5. 页面可直接放到 GitHub Pages 子目录运行。
6. Worker 不可用时前端回退本机记录，不崩溃。
7. 375px、390px、430px 宽度可用；CSV 导出字段正确。
